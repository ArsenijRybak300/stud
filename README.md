# StudentPlan — роли, группы, расписание и задания

Рабочая версия учебной информационной системы на React, FastAPI и PostgreSQL.

## Реализовано в этой версии

### Роли

- **Администратор**: создает группы и пользователей, формирует расписание по группам, создает задания, проверяет ответы и оставляет комментарии.
- **Студент**: видит расписание своей группы, берет задания в работу, прикрепляет файл и отправляет выполненную работу.

### Расписание

- расписание создается для группы, например `НМТ-333901`;
- занятие повторяется каждую неделю в пределах выбранного семестра;
- поддерживаются занятия каждую, по нечетным и по четным учебным неделям;
- расписание можно скопировать из предыдущего семестра в новый;
- отдельное занятие можно отменить только на конкретную дату с указанием причины, не удаляя его из недельного шаблона;
- студент не может редактировать расписание.

### Задания

Статусы без отдельного `revision`:

1. `assigned` — назначено;
2. `in_progress` — в работе;
3. `submitted` — отправлено на проверку;
4. `completed` — выполнено.

Администратор может написать комментарий и вернуть отправленное задание в работу. Отдельного статуса «на доработке» нет.

Файлы заданий и ответы студентов хранятся в постоянном Docker volume и не удаляются при обычном `docker compose down`.

## Первый запуск

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Адреса:

- приложение: `http://localhost:3000`;
- Swagger API: `http://localhost:8000/docs`;
- проверка backend: `http://localhost:8000/api/health`.

### Начальная учетная запись администратора

```text
Email: admin@studentplan.ru
Пароль: Admin12345
```

После первого входа создай необходимые группы и учетные записи. Для реального размещения обязательно измени пароль администратора и `SECRET_KEY` в `.env`.

Начальная группа создается автоматически:

```text
НМТ-333901
```

Студент также может зарегистрироваться самостоятельно, если введет код уже существующей активной группы.

## Обновление предыдущей версии

Эта версия содержит новую схему базы данных. Для чистого учебного запуска старую тестовую БД проще удалить:

```powershell
docker compose down -v
docker compose up --build
```

Команда `down -v` удаляет старые данные PostgreSQL и загруженные файлы. Применяй ее только при переходе со старой версии или когда данные не нужны.

Обычная остановка без удаления данных:

```powershell
docker compose down
```

Повторный запуск:

```powershell
docker compose up -d
```

## Проверка

Backend-тесты:

```powershell
cd backend
pytest
```

Проверяются регистрация, права ролей, групповое расписание, отмена отдельного занятия, перенос расписания между семестрами и полный цикл задания с загрузкой файла.

## Структура

```text
studentplan/
├── backend/       FastAPI, SQLAlchemy, Alembic, загрузка файлов, тесты
├── frontend/      React, TypeScript, Material UI
├── docs/          описание API и архитектуры
├── compose.yaml   PostgreSQL + backend + frontend
└── .env.example   параметры запуска
```


## Быстрый запуск через Docker

1. Перейдите в папку проекта:
```bash
cd studentplan_roles_groups_v1
```

2. Запустите контейнеры:
```bash
docker compose up --build
```

3. Откройте приложение:
- Frontend: http://localhost:3000
- Backend API: http://localhost:8000/docs

Данные администратора по умолчанию:
- Email: admin@studentplan.ru
- Пароль: Admin12345

Если авторизация не работает после старых запусков, очистите базу Docker и создайте её заново:
```bash
docker compose down -v
docker compose up --build
```
