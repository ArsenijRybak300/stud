# Архитектура StudentPlan

## 1. Общая схема

StudentPlan использует трехзвенную клиент-серверную архитектуру:

```text
Пользователь
    │
    ▼
React + TypeScript
    │ HTTP/JSON, Bearer JWT
    ▼
FastAPI REST API
    │ SQLAlchemy ORM
    ▼
PostgreSQL
```

При запуске через Docker Compose создаются три контейнера:

1. `frontend` — Nginx раздает собранное React-приложение и перенаправляет запросы `/api` на backend.
2. `backend` — FastAPI-приложение, бизнес-логика, проверка прав, работа с базой.
3. `db` — PostgreSQL, где постоянно хранятся пользователи, занятия и задания.

## 2. Backend

Точка входа: `backend/app/main.py`.

Основные уровни:

- `api/routes` — HTTP-маршруты;
- `schemas` — Pydantic-модели входных и выходных JSON-данных;
- `models` — SQLAlchemy-модели таблиц;
- `services` — бизнес-логика, не зависящая напрямую от HTTP;
- `core` — конфигурация и безопасность;
- `db` — подключение и базовый класс моделей.

### Поток запроса

Пример создания занятия:

```text
POST /api/lessons
       │
       ▼
JWT проверяется зависимостью get_current_user
       │
       ▼
JSON проверяется моделью LessonCreate
       │
       ▼
Создается объект Lesson
       │
       ▼
SQLAlchemy выполняет INSERT
       │
       ▼
LessonRead превращается в JSON
```

## 3. Авторизация

1. Пользователь регистрируется или входит.
2. Пароль никогда не хранится открытым текстом: используется `scrypt` со случайной солью.
3. Backend создает JWT с идентификатором пользователя в поле `sub`.
4. Frontend хранит токен в `localStorage` и отправляет заголовок:

```text
Authorization: Bearer <token>
```

5. Каждый защищенный маршрут определяет пользователя по токену.
6. Все запросы к занятиям и заданиям дополнительно фильтруются по `user_id`.

## 4. Модель данных

### users

- `id` — первичный ключ;
- `email` — уникальный логин;
- `full_name` — имя;
- `hashed_password` — хеш пароля;
- `created_at` — дата регистрации.

### lessons

- `user_id` — владелец;
- `subject` — дисциплина;
- `teacher` — преподаватель;
- `room` — аудитория;
- `lesson_type` — лекция, практика и другое;
- `weekday` — день от 0 до 6;
- `start_time`, `end_time` — время;
- `week_type` — каждую, нечетную или четную неделю;
- `notes` — заметка.

### assignments

- `user_id` — владелец;
- `lesson_id` — необязательная связь с занятием;
- `title`, `description` — содержание;
- `due_at` — срок;
- `status` — `todo`, `in_progress`, `done`;
- `priority` — `low`, `medium`, `high`.

Связи:

```text
users 1 ───── * lessons
users 1 ───── * assignments
lessons 1 ─── * assignments
```

## 5. Определение ближайшего занятия

Алгоритм находится в `backend/app/services/schedule.py`:

1. Получить текущее локальное время в настроенном часовом поясе.
2. Перебрать текущий день и следующие 14 дней.
3. Сопоставить день недели занятия с календарной датой.
4. Проверить четность ISO-недели.
5. Исключить занятия, которые уже начались.
6. Выбрать минимальную дату и время среди оставшихся.

## 6. Frontend

- `context/AuthContext.tsx` — состояние авторизации;
- `api` — функции работы с REST API;
- `pages` — страницы приложения;
- `components` — общие компоненты и формы;
- `types.ts` — TypeScript-интерфейсы данных.

Axios-перехватчик автоматически добавляет JWT. При ответе `401` сессия очищается и пользователь перенаправляется на вход.

## 7. Миграции

Alembic хранит историю изменений схемы базы в `backend/alembic/versions`.

Команда:

```bash
alembic upgrade head
```

применяет все миграции. При запуске backend-контейнера она выполняется автоматически.
